# 📋 Бизнес-требования

## 📌 TL;DR

Система нужна, чтобы гости находили и бронировали номера онлайн, а менеджеры и администраторы управляли отелями, бронями и отчётами. MVP включает весь текущий функционал: каталог, поиск, бронирование, отзывы и обе панели управления. Вне MVP — платёжный шлюз, уведомления, мультиязычность и мобильное приложение.

## 🎯 Цели и задачи проекта (Business Goals)

| ID | Цель | Задача | Связанные метрики |
|----|------|--------|-------------------|
| BG-001 | Упростить бронирование | Сократить путь гостя от поиска до брони до нескольких шагов | Конверсия поиск → бронь |
| BG-002 | Прозрачность доступности | Показывать свободные номера на выбранные даты | Доля успешных поисков |
| BG-003 | Централизовать управление | Дать менеджеру единый интерфейс для броней, номеров и отчётов | Время обработки брони |
| BG-004 | Контроль доступа | Разделить роли гостя, менеджера и администратора | Инциденты прав доступа |
| BG-005 | История взаимодействий с гостем | Хранить отзывы и историю бронирований | Количество отзывов |
| BG-006 | Масштабируемость архитектуры | Разделить монолит на сервисы без изменения UX | Количество сервисов, простота расширения |

## 👥 Целевая аудитория и персоны

| Персона | Роль в системе | Главные цели | Боли |
|---------|----------------|--------------|------|
| 🧳 Гость | `client` | Найти отель, выбрать номер, забронировать, отменить, оставить отзыв | Не понимает, есть ли свободные номера на нужные даты |
| 🧑‍💼 Менеджер отеля | `manager` | Управлять бронями, номерами, смотреть загрузку и выручку | Ручной учёт в таблицах, сложно видеть загрузку |
| 🛠️ Администратор | `admin` | Управлять пользователями, клиентами, данными и настройками системы | Нет единого контроля целостности данных |

## 🛡️ Нефункциональные требования (NFR)

| ID | Требование | Описание |
|----|------------|----------|
| NFR-001 | Производительность | Отклик интерфейса должен оставаться комфортным при типовых нагрузках; числовые SLA не заданы, цели описаны качественно. |
| NFR-002 | Безопасность | Пароли хранятся только в виде хеша; доступ к разделам определяется ролью; сессии — через Flask-Login. |
| NFR-003 | Защита данных | Секреты и параметры БД хранятся в `.env`, а не в коде. |
| NFR-004 | Масштабируемость | Сервисы запускаются отдельными процессами и могут масштабироваться независимо. |
| NFR-005 | Отказоустойчивость | Gateway проверяет готовность сервисов перед приёмом запросов. |
| NFR-006 | Доступность | Формальный стандарт WCAG не зафиксирован; интерфейс должен сохранять читаемость и работоспособность с клавиатуры. |
| NFR-007 | Локализация | Интерфейс только на русском языке. |
| NFR-008 | Совместимость | Поддержка современных браузеров; Bootstrap и Font Awesome загружаются с CDN. |
| NFR-009 | Тестируемость | Бизнес-логика разделена по сервисам; рекомендуется покрыть её автоматическими тестами. |
| NFR-010 | Поддерживаемость | Карта маршрутов и реестр сервисов вынесены в отдельные модули. |

## ✅ Критерии приёмки ключевых сценариев

| ID | Сценарий | Критерий приёмки |
|----|----------|------------------|
| AC-001 | Регистрация | Пользователь видит форму; после валидной отправки создаётся `User` и связанный `Customer`, происходит редирект на `/auth/login`. |
| AC-002 | Вход | При верных данных пользователь попадает на страницу в зависимости от роли (`/search`, `/manager`, `/admin`). |
| AC-003 | Поиск | На странице результатов отображаются только отели со свободными номерами на выбранные даты. |
| AC-004 | Бронирование | После отправки формы создаётся `Booking` со статусом `pending` и рассчитанной `total_price`. |
| AC-005 | Отмена брони | Статус меняется на `cancelled`, заполняется `cancelled_at`, бронь исчезает из активных. |
| AC-006 | Отзыв | Отзыв можно оставить только для существующей брони; после сохранения он виден на странице отеля. |
| AC-007 | Права доступа | Гость не попадает в `/manager` и `/admin`; менеджер не попадает в `/admin`. |
| AC-008 | Менеджер | Менеджер меняет статус брони, и изменение отображается в списке. |
| AC-009 | Администратор | Администратор создаёт пользователя с заданной ролью, и новый пользователь может войти. |
| AC-010 | Ошибки | Несуществующий ID возвращает 404; при internal error отображается понятное сообщение, а не стектрейс. |

## 📦 Scope: MVP

### ✅ Входит в MVP

- Регистрация, вход, выход, роли.
- Каталог отелей и номеров.
- Поиск и проверка доступности.
- Создание и отмена брони.
- Отзывы.
- Панель менеджера: брони, отели, номера, клиенты, платежи, отчёты, загрузка.
- Панель администратора: пользователи, клиенты, брони, платежи, отзывы, настройки, бэкап.
- Микросервисная структура с gateway.
- Тестовые данные и SQL-триггеры в репозитории.

### ❌ Не входит в MVP

- Реальная оплата и интеграция с платёжными системами.
- Email/SMS-уведомления.
- Английский и другие языки интерфейса.
- Мобильное приложение.
- Публичный JSON REST API.
- Формальное соответствие WCAG.
- Автоматизированный CI/CD и полный набор автотестов.
